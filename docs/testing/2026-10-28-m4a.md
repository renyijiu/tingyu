## 为什么用 AudioToolbox

mygo 0.7.1 只带 MP3、WAV 和 Vorbis 解码，没有 AAC。考虑过三条路：

| 方案 | 结论 |
| --- | --- |
| 通过 purego 调用 AudioToolbox 的 `ExtAudioFile` | 采用。不用 cgo，交叉编译照旧；mygo 的音频输出本来就这样调用 AudioToolbox。系统框架不随应用分发，没有新的许可条款。会自动去掉编码器的前置帧，按帧精确定位 |
| 通过 cgo 调用 AudioToolbox | 不采用。构建要依赖 C 编译器，也不能再从其他系统编出 macOS 包 |
| 纯 Go 的 MP4 解封装加 AAC-LC 解码器 | 不采用。找到的几个解码库都是 LGPL 或 GPL（有的是 FAAD2 或 FFmpeg 的移植），和静态链接的 MIT 应用不好搭配；而且大多不支持 HE-AAC |

AudioFile 通过回调读文件（`AudioFileOpenWithCallbacks`），读到还没下载的部分时，回调在 `media.Reader` 上等待。所以文件只要先给出索引就能边下边播；超过文件长度的读取立刻返回，不会等下载结束。

## 小宇宙的文件

- 「岩中花述」（`https://feed.xyzfm.space/hwen8wf69c6g`）87 集全是 `.m4a`。音频地址先 302 到 `media.xyzcdn.net`，支持 Range。
- 编码是 AAC-LC，44.1 kHz 立体声，约 128 kb/s，用 ffmpeg（Lavf）封装。
- 抽查的 4 集都把 `moov` 紧放在 `ftyp` 后面（225 KB 到 1.16 MB）。打开一个 108,296,876 字节的文件时，AudioFile 只读了前 1,155,143 字节，也就是 `moov` 加上 `mdat` 的头。
- 音频 CDN 接受新旧两种 User-Agent；RSS 地址 `feed.xyzfm.space` 只接受不含 `github.com` 的那种。

真实引擎这几项用的是会话里临时写的程序：接线和 `main.go` 一样（`app`、`store`、`media`、`player`、`mygoengine`），但没有窗口，像界面那样每 250 毫秒调一次 `Tick`。本分支还没有小宇宙的 User-Agent 修复，所以程序抓 RSS 时把 `feed.Fetcher.UserAgent` 设成了修复后的 `Tingyu/0.1.0 (renyijiu/tingyu)`；下载音频用的是本分支原来的 User-Agent。程序没有提交到仓库。

## 尚未验证与已知限制

1. **原生窗口**：没有在窗口里点按播放 M4A，也没有用眼睛确认「正在播放」的光晕随 M4A 的响度起伏。响度数据本身已经在引擎测试和上面的真实播放里确认。
2. **索引在末尾的 M4A**：要等整个文件下载完才开始播放，和 MP3 一样。抽查的小宇宙文件都没有这种情况，只用测试文件验证过。
3. **慢网络**：这次下载很快（108 MB 约 5 秒），没有测过跳到远处、要等很久的情况。等待时界面的表现和 MP3 一样。
4. **其他 AAC 形式**：没有测 HE-AAC 文件；裸 ADTS 流（`.aac`）没有注册；带视频的 MP4 没有测。
5. **只有 macOS 能解码**：其他系统能识别 M4A，但打开会报错。

## 复测步骤

```bash
go test -race ./...
go vet ./...
```

用独立目录启动原生窗口。要先合入小宇宙的 User-Agent 修复，否则 RSS 会返回 403：

```bash
export TINGYU_DATA_DIR="$(mktemp -d /tmp/tingyu-m4a.XXXXXX)"
go tool mygo dev
```

1. 搜索「岩中花述」并订阅，打开最新一集。
2. 确认几秒内开始出声，进度推进，「正在播放」的光晕随声音起伏。
3. 拖到中间，切到 1.5×，后退 15 秒。
4. 暂停后退出，在同一终端再运行 `go tool mygo dev`。确认单集显示已保存的进度，点播后从那里续播。
5. 下载还没完成时切到故事FM的一集 MP3，确认数据目录的 `cache/` 里没有残留的 `.part` 文件。
