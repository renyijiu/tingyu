## 改了什么

| 改动 | 之前 | 现在 |
| --- | --- | --- |
| 节目简介 | 从 iTunes 搜到的节目没有简介；Podcast Index 的简介被截到 100 个词 | 打开节目后用 RSS 里的简介；作者、封面、链接缺的也从 RSS 补上 |
| 单集列表 | 每次打开都完整下载、解析 RSS，1 到 10 MB | 先显示上次的列表，同时带上 ETag / Last-Modified 去问 RSS 有没有更新；RSS 读不到时沿用上次的列表，不退回 iTunes，单集的身份不变 |
| RSS 大小 | 超过 20 MB 被截断，解析报错 | 上限 64 MB，超过时明确报「larger than」 |
| 封面 | 原图解码后留在内存里，不释放 | 缩小到 640 像素以内，存进磁盘；内存最多 120 张 |
| 搜索 | 先问 Podcast Index，出错或没结果才问 iTunes，最坏要等 20 秒 | 两边同时问，按 RSS 地址去重合并，标题和关键词一样的排最前；一边先有结果后最多再等 2 秒 |
| 「发现」页 | 写死的推荐词 | 推荐词下面是 Apple 播客中国区榜单前 24 档；加载失败时一分钟后再试 |
| Podcast Index 单集 | 最多 200 集，简介截断 | 最多 1000 集，带 `fulltext` |

## 遇到的问题

原生窗口截图跑了五次：

- 有一次榜单 20 秒内没加载出来，临时程序自己因为空列表崩了，应用本身没问题。原因没查实，可能是测试期间对 iTunes 请求太多，触发了它每分钟约 20 次的限流。这之后加了「加载失败一分钟后再试」，之前一次失败就整场不再请求。
- 还有一次截图里设置弹窗是开着的。代码里只有点提示条或侧栏的「设置」才会打开它；测试窗口是置顶弹出的，最可能是被鼠标点到了。之后几次都没有再出现。

## 尚未验证与已知限制

1. **Podcast Index**：没有密钥，合并搜索只用 iTunes 跑过真实请求。`fulltext` 发的是 `fulltext=`（官方文档写的是不带值的 `fulltext`），没有实际确认服务端认这种写法。
2. **榜单**：Apple 的榜单 JSON 是给营销工具用的，没有作为 API 正式写进文档。它变了或不能用时，「发现」页会退回原来的空状态。
3. **小宇宙和喜马拉雅的 RSS** 都不返回 ETag 和 Last-Modified（2026-10-29 用「岩中花述」和「声动早咖啡」查过，后者 10 MB），所以每次打开还是会完整下载一遍；只是先显示上次的列表，用户不用等。
4. **榜单固定是中国区**，没有跟着系统的地区走。
5. **没有密钥时**仍然只搜 iTunes。Podcast Index 的免密钥搜索接口没有接入。
